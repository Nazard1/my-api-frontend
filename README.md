# Клювання — фронтенд каталогу товарів

Фронтенд інтернет-магазину «Клювання»: каталог товарів, реєстрація, вхід і додавання товару через REST API з JWT-авторизацією. HTML + CSS + jQuery (з CDN), без фреймворків, збирання й залежностей.

Бекенд: [Nazard1/my-api-project](https://github.com/Nazard1/my-api-project).

## Функціонал

| Сторінка | Доступ | Що робить |
| --- | --- | --- |
| `index.html` | усі | Таблиця товарів (назва, бренд, категорія, ціна, залишок) |
| `register.html` | лише гості | Реєстрація; після успіху веде на вхід |
| `login.html` | лише гості | Вхід; після успіху повертає на сторінку з `?next=` або на головну |
| `add-product.html` | лише авторизовані | Форма створення товару; категорії й бренди підтягуються в списки з API |

- **Навігація.** Гість бачить «Увійти» й «Реєстрація», авторизований — своє імʼя й «Вийти». «Вийти» видаляє токени й веде на головну.
- **Токени.** Після входу `access`, `refresh` і `username` зберігаються в `localStorage`; запити на зміну даних надсилають заголовок `Authorization: Bearer <access>`.
- **Редіректи.** Гість на `add-product.html` потрапляє на `login.html?next=add-product.html` і після входу повертається назад. Параметр `next` приймає лише назву сторінки цього сайту (`add-product.html`), повні адреси на інші сайти ігноруються. Авторизованого з `login.html` і `register.html` перекидає на головну.
- **Автооновлення токена.** Access-токен живе 5 хвилин. Якщо сервер відповів `401`, обгортка `apiRequest` (у `auth.js`) один раз отримує новий access через `/auth/refresh/` і повторює запит. Якщо й refresh недійсний — токени видаляються, відкривається сторінка входу.
- **Помилки.** Помилки перевірки (`400`) показуються біля відповідних полів форми, інші — під формою. Увесь текст із сервера вставляється через `.text()` (захист від XSS).

| Файл | Призначення |
| --- | --- |
| `auth.js` | Спільний код: адреса API, токени, навігація, редіректи, `apiRequest`, показ помилок форм |
| `app.js` | Каталог товарів |
| `register.js`, `login.js`, `add-product.js` | Логіка відповідних сторінок |
| `style.css` | Стилі |

## Як запустити проєкт

1. Запустіть бекенд за інструкцією в його README (розділ «Як запустити проєкт»): [github.com/Nazard1/my-api-project](https://github.com/Nazard1/my-api-project). Бекенд має працювати на http://127.0.0.1:8000.
2. В окремому терміналі клонуйте фронтенд і запустіть статичний сервер у його папці (потрібен Python):

   ```powershell
   git clone https://github.com/Nazard1/my-api-frontend.git
   cd my-api-frontend
   python -m http.server 5500 --bind 127.0.0.1
   ```

3. Відкрийте http://127.0.0.1:5500.
4. Щоб додати товар: «Реєстрація» → «Увійти» → «Додати товар». Список категорій і брендів у формі береться з бекенду, тож спершу вони мають бути створені (через адмінку або Postman-колекцію бекенду).

Якщо бекенд не запущено, сторінка покаже повідомлення «Не вдалося отримати дані з API…».

| Що | Адреса | Порт |
| --- | --- | --- |
| Фронтенд | http://127.0.0.1:5500 | 5500 |
| Бекенд | http://127.0.0.1:8000 | 8000 |
| API | http://127.0.0.1:8000/api/v1/ | 8000 |

## Навіщо CORS

Фронтенд (`http://127.0.0.1:5500`) і бекенд (`http://127.0.0.1:8000`) працюють на різних портах, тобто це різні origin. Браузер за замовчуванням не дає сторінці читати відповіді з іншого origin (політика same-origin), тому бекенд має явно дозволити цей доступ заголовком `Access-Control-Allow-Origin`. У бекенді це робить `django-cors-headers`, а дозволені адреси задаються змінною `CORS_ALLOWED_ORIGINS` у файлі `.env`. Адреса фронтенду має бути в цьому списку (за замовчуванням там уже є `http://127.0.0.1:5500` і `http://localhost:5500`), інакше браузер заблокує відповідь і сторінка покаже повідомлення про помилку.
